# hybrid undo: bounded model observations and remaining choices

Ren supplied an executable event-set model and report against PR1 at26bf8be. Lynn replayed the unchanged Python script using Python from pinned nixpkgs7d1a7c21a4c00ea653fc7ed5c083d261340f185f. The supplied sources and output are retained locally; this document records the scope and consequences, not an implementation adoption.

The model contains creation IDs, deletion effects, restoration pairs `(deletion ID, element ID)` and cancellation of named restoration events. It calculates a **set** of visible IDs. It does not integrate text positions or implement a general history-selection algorithm. Undo/restoration events are supplied by the fixtures rather than generated by a complete session implementation.

## constraints the examples expose

### restoring part of a replacement

Alice creates old-b; Bo atomically deletes old-b and creates new-x. Ren wants restoration of old-b while new-x remains. The model's whole-replacement on/off interpretation can produce either singleton, not both IDs. The requested behavior therefore needs an addressable deletion effect or another operation capable of restoring that part. This does not require splitting the original atomic edit or its ordinary user-visible item into separate actions. Nor does the visible-ID set determine the order of b and x.

### selection is fixed when the writer presses undo

Bo has an older insertion z, then deletes Alice's b. While disconnected from each other, Alice restores b and Bo selects his own deletion for undo. If a receiver interprets Bo's message by selecting again against its current state, delivery order can make it skip that deletion and remove z. The supplied two-message control exhibits both `{b}` and `{b,z}`.

An event naming the deletion Bo actually selected preserves z in both orders. If Bo first receives Alice's restoration and then selects his older z, that is a different authored action. A receiver must not turn the former into the latter. The eventual wire/selection specification must preserve this distinction without replicating a private stack.

## redo is still a policy choice

Start with one b and one deletion D. Alice and Bo independently restore D, exchange those decisions, then Alice presses redo.

| candidate interpretation | model result | meaning |
| --- | --- | --- |
| retract only Alice's named restoration | b remains | Bo's independent restoration still suppresses D |
| retract both observed restorations | b disappears | Alice reapplies the deletion reversed by that shared round |

Both authored event sets pass the bounded delivery replay. That cannot choose the intended behavior. The second option is not a proven shared-round protocol: the fixture supplies a cancellation set containing both restoration IDs. Eligibility, concurrent later restorations, repeated cycles and what the other session selects next remain unspecified. The first option also needs complete session/redo rules. Neither is adopted.

## a remaining conflict with q07

The fixture “independent concurrent deletion remains effective” has two deletions of old-b and a restoration addressing only one. It leaves old-b hidden. Ren's q07 instead asks for b after Alice undoes her deletion despite Bo's independent deletion.

Keep q07 as a requested outcome rather than silently changing it to match the candidate. Specify what suppresses the other deletion, what happens if it arrives late, and what Bo can subsequently undo/redo. This changes the candidate's effect rule; passing the other fixtures does not settle it. Mixed-author deletion and partial-restoration fixtures similarly instantiate hypotheses, not already accepted policy.

## recovery without shared undo stacks

Bo and Cam independently delete old-b. In history H1 Alice restores Bo's deletion D; in H2 she does not. Cam's deletion hides b in both. A resumed Bo session has the same private stack `[D,Z]` and the same visible ID set in both histories. Under the fixture's skip rule, the next target is Z in H1 and D in H2.

This demonstrates why **that rule** requires a receiver to retain which deletion was restored, beyond visible text/IDs. It does not require sharing Bo's private stack: a new session with no stack selects nothing in both histories. This respects Ren's q39 clarification about device-local undo history while distinguishing it from shared semantic facts used to interpret later operations.

The model's cold copy serializes the full event dictionary and reconstructs it directly, without ordinary admission. It checks faithful event-set replay, not a compact codec, validated loading, authentication, authority, parser safety or checkpoint persistence. V8 remains unfulfilled.
